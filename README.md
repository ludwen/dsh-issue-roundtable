# 议题圆桌（dsh-issue-roundtable）

DSH Desktop 的工作台插件：以**图形化的圆桌会议**组织多角色 agent 辩论，讨论收敛后由全体投票表决出一个方案。

## 界面

工作台是整页业务面板，顶部只有一条紧凑工具栏，两个入口：**议题** 与 **角色库**。

### 议题（列表 + 详情）

- **列表**：每个议题一行卡片，显示标题、状态、轮次/发言数、参与者头像条、结论摘要；支持按状态筛选（未开始 / 待决定 / 讨论中 / 表决中 / 已表决）和关键字搜索（标题、目标、角色名）。
- **详情**：上半部分是**圆桌**——参与者按椭圆就座并带各自颜色与发言计数，谁在发言谁的头像发光，中间气泡显示「正在发言 / 书记员收敛中 / 已产生结论」。
- **点座位 = 只看这个角色的发言**，再点一次取消；右侧是轮次/发言/角色/阶段四个统计卡与操作区（开始讨论 / 继续讨论 +2 轮 / 进行表决 / 取消）。
- 下面是**发言记录**：按轮次分段，每段可切「详细 / 紧凑」，长发言默认折叠成 3 行、点「展开全文」看完整段落，还有**全屏阅读抽屉**（右侧大面板，带同样的筛选与密度控制）。
- 表决后展示**候选方案**（胜出者高亮 + 得票与投票人）、**投票明细**（含平票复选）、**结论卡**（方案要点/取舍/票数/少数意见/待解决问题，可一键复制）。

### 越长越能聊

轮数只是**起点**：跑完计划轮数后停在「待决定」，可以继续追加（每次 +1~8 轮）。追加时角色收到「这是追加讨论，只解决还没定的分歧」的任务提示，不会重复已达成一致的内容。已有结论后继续讨论，结论会被标记为**待复核**而不是被删除。

### 新建议题（向导）

三个步骤，可来回切换：

1. **AI 起草**：把想法说出来，AI 每轮追问一个关键问题，并持续给出完整草稿（标题 / 背景 / 目标 / 核对清单）；信息够了才自动跳到下一步，追问阶段不会被弹走。
2. **议题内容**：AI 定稿后可手改标题（必须是能被赞成/反对的问题句）、背景、希望产出、核对清单。
3. **角色与顺序**：按**分组**筛选角色库，点选参与角色（2~8 位），选中的角色出现在下方**发言顺序**列表，可拖拽或点 ↑↓ 调整；同页设置计划轮数与是否联网检索。

### 角色库

- 左侧是**分组**（核心决策 / 风险与合规 / 客户与一线，可增删改），右侧是该分组的角色卡片；删除分组时其角色会迁移到第一个分组，不会丢。
- 新建/编辑角色：名称、关注点、分组、立场与说话方式（至少 20 字）。
- **AI 帮我写角色**：一句描述 → 2~3 个差异明显的候选（名称/关注点/立场），点候选直接填入表单再微调。

### 团队化管理（Agent 建组 / 批量改写）

角色库支持**按组与按角色多选**，并由 Agent 批量处理：

- **AI 建团队**：描述一个决策场景（例如「我想建一个个股投研组，判断某只股票值不值得买」）→ Agent 一次给出**分组 + 4~6 个互补角色**。可选「写满人设」或「只出框架（人设待补）」。预览里能改分组名、逐个改名称/关注点/人设、移除角色，确认后**整组一次落库**。
- **选中范围改写**：勾选整个分组（左侧分组前的复选框）或勾选若干角色 → 输入一句话要求（例如「整体更保守，都要先问下行风险」）→ Agent 逐个改写并给出**前后对照**，你可以逐个勾选接受，只把勾选的写入库里，未勾选的保持原样。
- **模型工具**：宿主注册了 `roundtable_library`（读/整体写回分组与角色）和 `roundtable_team`（生成一个分组与其全部角色），所以对话里的 Agent 也能直接管理角色库，不必你手动点。

## 讨论与表决流程

```
议题（标题 + 背景 + 目标 + 核对清单）
  └─ 联网检索（可选，一次，全体共享）
      └─ 第 1..N 轮：按你设定的顺序依次发言（每轮每人一次真实模型调用）
          └─ 停在「待决定」——可继续追加轮次，直到收敛
              └─ 书记员：把讨论收敛成 2~4 个可表决方案
                  └─ 全体投票（每人一票 + 理由）
                      └─ 多数票胜出 / 平票自动复选一轮 / 仍平票由书记员推荐裁定
                          └─ 结论卡 + 少数意见 + 待解决问题
```

引擎跑在宿主进程：切工作台、关面板、刷新页面都不会中断讨论。

## 安装

```bash
pnpm pack          # 产物 dsh-issue-roundtable-<version>.tgz
```

把 `.tgz` 装进当前 profile（Desktop 内由 Agent 调用 `install_local_workbench` 或插件管理安装），重启 Harness，展开左侧栏，在左上角「工作台」右侧的切换区域选择「议题圆桌」。

**关于 `register()` 里的 `repository`**：Desktop 0.12.x 会丢弃无法归属到单一仓库的工作台提供方，只有 0.13.0 起才支持纯本地身份 `local:<npm 包名>`。为兼容 0.12.1，客户端注册写入了 `https://github.com/ludwen/dsh-issue-roundtable`（作者自己的 GitHub 命名空间，仓库名与 npm 包名一致，仓库已创建且代码就在此仓库）。它只用于稳定身份，不发布任何内容；升级到 0.13.0 后既有归属继续有效。

## 数据位置

业务数据在插件配置的 `root`（默认 `$DSH_HOME/issue-roundtable`）：

| 文件 | 内容 |
|---|---|
| `groups.json` | 角色分组 |
| `roles.json` | 角色库 |
| `issues.json` | 议题列表与每场会议的完整记录（发言、方案、投票、结论），默认最多 200 条 |

卸载插件不会删除这些文件。

## 结构

```
package.json            npm 与 DSH 插件声明
cordis.patch.yml        把宿主入口插进插件树（name 必须写包名）
dsh/index.js            宿主：分组/角色/议题存储、讨论与表决引擎、AI 助手、/api/issue-roundtable 路由
src/client/             客户端源码（拆分维护）
  index.js              模块入口与各视图组件（手写，无 JSX）
  shared.js             请求、时间、颜色、状态等纯函数
  roundtable.js         圆桌座位布局与气泡（参考实现，产物内联）
  views.js              议题列表、发言记录、抽屉（参考实现，产物内联）
  detail.js             议题详情与结论卡（参考实现，产物内联）
  wizard.js             议题向导（参考实现，产物内联）
  library.js            角色库（参考实现，产物内联）
  styles.css            全部样式（作用于 .rtr 作用域）
scripts/build-client.mjs  把 styles.css 内联进 src/client/index.js → lib/client.js
lib/client.js           构建产物，Desktop 实际加载的单文件模块
locale/{zh,en}.json     市场与卡片用的名称、简介
test/smoke.mjs          宿主引擎离线测试（假模型 + 假 ctx）
test/panel.mjs          面板在 jsdom 下的渲染与交互测试
test/installed.mjs      用 Desktop 的模块回退导入「已安装」的包并挂载
test/register.mjs       用真实 Workbenches 服务校验 register()
test/live.mjs           对运行中的 Host 跑真实模型讨论
```

## 自测

```bash
node scripts/build-client.mjs   # 先构建客户端产物
node test/smoke.mjs             # 66 项：分组/角色、议题 CRUD、轮次、追加、表决、平票、AI 助手、团队与范围改写、校验
node test/panel.mjs             # 64 项：圆桌、列表筛选、长文本折叠/抽屉/密度/筛选、向导、角色库、团队向导、多选改写
node test/installed.mjs <已安装的包目录>
node test/register.mjs
node test/live.mjs <token-url>  # 会真实调用模型
```

`node_modules/` 只用来把宿主的 `@deepseek-ai/*` 包链接进来，不进版本库。前四个不联网、不读真实模型。`test/panel.mjs`、`test/register.mjs` 从 DSH 安装目录借用 `jsdom`、`react`、`react-dom` 与真实的 `dsh-desktop-workbenches/client.js`（路径写在脚本顶部）；`test/live.mjs` 通过认证 cookie 调运行中的 Host。

## 已知限制

- 发言是**串行**的：一位角色一位角色地调用模型，一轮 4 个角色大约 1~3 分钟；投票是并行的。
- 角色没有工具能力，只输出观点文字；联网资料由工作台统一检索后共享，避免每个角色各自搜索带来的高延迟与高费用。
- 议题记录保存在本机，不做云同步，超过上限会裁掉最旧的。
- 讨论引擎依赖宿主进程：卸载插件或重启 Harness 时进行中的讨论会被取消并记为「已取消」。
- `src/client/roundtable.js`、`views.js`、`detail.js`、`wizard.js`、`library.js` 是同一份 UI 的模块化参考实现；Desktop 只加载构建产物 `lib/client.js`（由 `index.js` + `styles.css` 组装），两者若改动需要同步。
